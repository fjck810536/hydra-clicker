# Playtest 4.2 — NP 倒數與令咒 II 第一段技法

> 日期：2026-09-08  
> 性質：玩家端工作紀錄。這份文件記錄已觀察到的體感、下一個可測假說，以及仍刻意不固定的數值。

## 1. Playtest 4.1 實機回報

目前可以先保留三個觀察：

1. **Hydra I 的寶解／時停手感可以接受。**
2. **Hydra II 在 3 秒純手砍期間會出現明顯「砍不動」感。**目前不把這直接判定成 NP duration 太短；因為令咒 II 尚未加入，這個阻力反而可能自然製造下一個升級需求。
3. **規則層次已開始被感覺到。**普通 Auto、Hydra II 的增殖、寶解禁止生長、寶解期間 Auto 停止與手動輸出，已不再只是單一 clicker 數值線。

因此 Playtest 4.2 的方向不是立刻把 3 秒拉長，而是先驗證：

> 玩家能不能透過新的「寶具技法」在相同三秒內變強。

---

## 2. NP 倒數碼表

寶解期間顯示一個小型倒數：

```text
TIME STOP
3.0 s
MANUAL ×1
```

以約 0.1 秒粒度往下顯示：

```text
3.0
2.9
2.8
...
0.1
```

目的不是精密計時工具，而是把「只有三秒」變成玩家可以直接感受到的壓力與笑點。

倒數必須跟真正的 NP simulation-time window 對齊；不能由 CSS 動畫自行計時。

---

## 3. Command Spell II — Lv.1 prototype

目前只確認第一段效果，不確認正式經濟與完整升級樹。

### NP 外

```text
1 tap
→ 1 cut
```

完全不變。

### NP / TIME STOP 內

令咒 II Lv.1：

```text
1 tap
→ CUT
→ CUT
→ CUT
```

也就是：

> **1 次玩家點擊 = 3 次離散的手動斬擊。**

這三刀不是 `heads -= 3` 的單一傷害，而是三次真正的 cut resolution；每一刀都應有自己的 semantic cut，而且畫面應盡量讀成快速三連斬。

Hydra II + NP 時，例如：

```text
9
→ tap
→ 8
→ 7
→ 6
```

因為 NP 已禁止 head growth，每一刀都是真正的 net -1。

---

## 4. 為什麼先做 ×3，不先延長 NP

目前 Hydra II 的「三秒內砍不動」可能是一個有用的斷點：

```text
原本以為寶解就是答案
↓
寶解確實讓蛇停止生長
↓
但玩家自己的輸出又不夠
↓
新的需求出現：如何在停止的時間裡砍得更有效？
↓
Command Spell II
```

這比直接把 NP 從 3 秒調成很長，更能保留機制層次。

因此在 ×3 實測以前：

- 不因「砍不動」直接 buff NP duration。
- 不恢復 Auto Slash 進入 NP。
- 不提前實作 6-hit / 9-hit。
- 不提前實作 81 秒級長時停。

## 6. 這輪實測方式

TEST 直接提供 Hydra II 的 81-head cap，避免先跑蛇一或讓 Auto 影響比較。

### A｜原本三秒純手砍

```text
TEST
→ HYDRA II · 81 HEADS
→ NP READY
→ NP RELEASE
→ 狂點三秒
```

### B｜令咒 II ×3

```text
TEST
→ COMMAND SPELL II · ×3 NP
→ HYDRA II · 81 HEADS
→ NP READY
→ NP RELEASE
→ 狂點三秒
```

`MAX COMMAND SPELL` 在這輪比較中不需要開，因為 NP 時停內 Auto 本來就暫停。

重點不是「B 一定要三秒殺 81」，而是比較：

> ×1 時的「完全砍不動」是否在 ×3 後變成「有明顯推進、差一點、想再強一級」。

---

## 7. Playtest 4.2 要回答的問題

1. **×3 是否把 Hydra II 從「完全砍不動」推到「差一點／有機會」？**
2. 3.0 → 0.0 的可見倒數是否讓寶解更緊張、更好笑，還是反而太佔注意力？
3. 一點三刀在手機連點時是否夠容易讀懂？
4. 三連斬視覺是否真的讀成三刀，而不是一個抖動動畫？
5. 如果 ×3 成立，玩家是在什麼時候自然想要它？這個時間點才用來決定正式解鎖節點與價格。

核心原則：

> **先確認技法讓三秒變得好玩，再決定技法要賣多少錢。**
