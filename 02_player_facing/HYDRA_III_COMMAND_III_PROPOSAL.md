# Hydra III + Command Spell III — Player-Facing Proposal

> Status: **provisional player-facing design proposal**.
>
> Scope: Hydra III experiential role, >99-head abstraction, Tree-view reveal, Command Spell III identity, and the first cross-system numerical relationship between Command Spell I / II / III.
>
> This file does not define implementation. Anything outside `02_player_facing/` remains read-only context for this discussion.

---

## 1. Why design Hydra III before finalizing Command Spell II

Current play experience suggests Command Spell II does **not** need to be completed inside Hydra II.

Hydra II can remain reasonably playable as long as the player understands:

> ordinary cutting grows the Hydra  
> → NP / time stop suppresses growth  
> → opening NP allows real progress

Therefore it is acceptable — and probably desirable — for a player to reach Hydra III with Command Spell II still partially upgraded.

This means Command Spell II should not be balanced as a Hydra-II completion checklist.

Hydra III should instead reveal what the **next limitation** of the player's current toolkit is.

Recommended chapter-level transition:

> Hydra II: "Only cutting during NP truly reduces the problem."  
> Hydra III: "Even manual cutting during NP is beginning to be too small for the scale of the problem."

That is the natural place for Command Spell III.

---

## 2. Hydra III scale

Current player-facing scale target:

> starting heads = **9**  
> maximum logical heads = **729 = 9^3**

### Preferred normal cut law

Do not add `GROW +3` merely because this is Hydra III.

The preferred provisional rule remains:

> **CUT 1 → GROW +2**

until a later structural mechanic genuinely needs a different law.

The novelty of Hydra III is **scale and representation**, not necessarily a new arithmetic rule.

### Cap state

At 729 logical heads, ordinary cutting can use the same perceptual stalemate grammar established by Hydra II:

> CUT → immediate replacement / recovery → still 729

The important difference is that the player can no longer literally see all logical heads.

---

## 3. Hydra III is the first generation where the number exceeds the monster

The main Hydra view remains capped at approximately:

> **99 visible heads**

Hydra III is the first generation where logical head count can exceed that visible ceiling.

Therefore the key experiential transition is:

> 99 visible heads  
> → logical counter continues: 100, 101, ... 729  
> → the visual monster is now only a projection of a larger mathematical object

The player should feel that **the number has escaped the image**.

This is a more important Hydra III novelty than adding elemental heads or a new status effect.

---

## 4. Tree View first reveal

### Preferred trigger

Tree View becomes available the first time Hydra III logical heads exceed the literal visual ceiling:

> **logical head 100**

The first reveal should answer:

> "If I cannot literally see every head anymore, where did the rest of them go?"

### Early Tree View role

At Hydra III, Tree View is still primarily observational.

It may expose:

- logical head count;
- rough branching / generation structure;
- an abstract representation of the population beyond the 99-head visual proxy;
- zoom / inspection;
- later-compatible generation labels.

It should **not yet require the player to choose individual structural nodes to cut**.

The intended cognitive step is:

> monster with heads  
> → population  
> → tree / structure

not yet:

> tree UI replaces combat.

---

## 5. Command Spell III — core identity

### Preferred text

Current preferred joke-text:

> **「這裡怎麼沒有 SKIP???」**

Exact wording / punctuation can still be polished later.

### Mechanical identity

Command Spell III solves the limitation that has been deliberately preserved through Hydra I and II:

> **Auto Slash normally pauses during NP / time stop.**

Command Spell III begins allowing the player's existing Command Spell I automation to enter the stopped-time Noble Phantasm state.

This gives the three Command Spells clean, non-overlapping identities:

### Command Spell I

> **How much automatic cutting exists in ordinary time?**

APS progression.

### Command Spell II

> **How strong / long is my manual Noble Phantasm state?**

NP-only manual multistrike, NP efficiency, longer time stop.

### Command Spell III

> **How much of my automation can cross into stopped time?**

Bridge Command Spell I into NP.

This triangular relationship is preferred over giving Command Spell III another unrelated damage multiplier.

---

## 6. Command Spell III should remain one simple slot

The fixed three-slot UI rule remains:

> `[令咒 I] [令咒 II] [令咒 III]`

Command Spell III must not expand into a separate skill tree.

Recommended compact internal ladder:

| Command Spell III state | Auto Slash allowed during NP |
|---|---:|
| before acquisition | **0** |
| Lv.1 | **1/9 of current Command Spell I APS** |
| Lv.2 | **1/3 of current Command Spell I APS** |
| MAX | **100% of current Command Spell I APS** |

This uses the same powers-of-three language without adding another complicated subsystem.

### Important restriction

Automatic attacks entering NP do **not** automatically inherit Command Spell II's manual multistrike.

Command Spell II remains about the player's own click becoming 3 / 6 / 9 rapid cuts.

Command Spell III remains about autonomous attacks being permitted inside stopped time.

This prevents the two systems from collapsing into one generic multiplier.

---

## 7. Why the 1/9 → 1/3 → 1 ladder is useful

It makes Command Spell III's effect immediately legible at any Command Spell I level.

Examples:

| Current Command Spell I APS | CS III Lv.1 | CS III Lv.2 | CS III MAX |
|---:|---:|---:|---:|
| 27 | 3 APS | 9 APS | 27 APS |
| 81 | 9 APS | 27 APS | 81 APS |
| 243 | 27 APS | 81 APS | 243 APS |
| 729 | 81 APS | 243 APS | 729 APS |

So Command Spell III does not invent a new speed scale. It simply lets increasing fractions of an already-understood speed cross the time-stop boundary.

---

## 8. Hydra III's key numerical identity: APS × time = 729

Once Command Spell III reaches full automation-in-NP, a very useful numerical symmetry appears:

> **243 APS × 3 s = 729 cuts**
>
> **81 APS × 9 s = 729 cuts**
>
> **27 APS × 27 s = 729 cuts**
>
> **9 APS × 81 s = 729 cuts**

This is not intended as a rigid guarantee that every Hydra III dies in exactly one window. Manual cuts, multistrike, current head count, activation timing, and other rules still matter.

But it is an excellent **player-facing balance benchmark**.

It means different Humanity Evil investment histories can converge on comparable stopped-time throughput:

### Automation-heavy player

> high Command Spell I APS  
> short / weak Command Spell II time  
> Command Spell III bridges the high APS into NP

Example target pair:

> 243 APS × base 3 s ≈ 729 automatic NP cuts

### Balanced player

> 81 APS  
> 9-second NP

Target pair:

> 81 × 9 ≈ 729

### Time-focused player

> only 27 APS  
> much longer 27-second NP

Target pair:

> 27 × 27 ≈ 729

### Extreme time-investment player

> only 9 APS  
> 81-second NP

Target pair:

> 9 × 81 ≈ 729

This gives Hydra III a strong reason to exist **before** Command Spell II values are fully sealed: Hydra III provides the scale against which Command Spell II's duration curve can be judged.

---

## 9. Command Spell III first-unlock trigger

Command Spell III should not require Command Spell II MAX.

It should also not require a particular Command Spell I APS level.

The preferred gameplay eligibility trigger is:

> **first Noble Phantasm release while fighting Hydra III**

Reason:

- Hydra III has already demonstrated the >99 / 729 scale;
- the player presses NP;
- Auto Slash visibly stops, exactly as it has always done;
- at this new scale, that old limitation suddenly becomes much more conspicuous;
- Command Spell III now has an immediately understandable purpose.

The teaching rhythm becomes:

> scale becomes absurd  
> → player opens NP  
> → all automation freezes  
> → "I need my automation in here too"  
> → Command Spell III becomes eligible

This is preferred over revealing Command Spell III arbitrarily at a kill counter milestone.

---

## 10. Anti-softlock requirement for Command Spell III

Unlike Command Spell II, Command Spell III does not need to be strictly required to kill the first Hydra III.

That distinction is important.

### Required safety condition

> **The first Hydra III must remain killable with the player's pre-Command-III toolkit.**

It may be slower or require repeated NP cycles, but it must not be a hard progression lock.

Therefore Command Spell III is a strong scale-breaking upgrade, not the only legal solution to the first Hydra III.

This gives pricing more freedom than Command Spell II.

However, if playtest shows that first-Hydra-III completion without Command Spell III is excessively tedious, either:

- the first Command Spell III purchase price must be guaranteed affordable at Hydra III entry, or
- Hydra III intro pacing must be adjusted.

Do **not** silently leave a circular economy where the player needs Command Spell III to earn the first Humanity Evil that would buy Command Spell III.

---

## 11. Candidate Command Spell III Humanity Evil curve

Pricing is intentionally less certain than the mechanic, because Hydra III's actual income timing is not yet playtested.

A compact first candidate, assuming Hydra III true kills later award **99 Humanity Evil** each:

| CS III level | Effect | Candidate cost |
|---|---|---:|
| Lv.1 | 1/9 APS during NP | **99** |
| Lv.2 | 1/3 APS during NP | **297** |
| MAX | full APS during NP | **891** |

This uses a simple 1 / 3 / 9 multiple of one Hydra III kill reward.

But the **mechanical ladder is higher-confidence than these prices**.

If anti-softlock testing requires the first purchase to be guaranteed at entry, the Lv.1 cost should be lowered or an entry reserve should be guaranteed rather than compromising Hydra III's combat rule.

## 12. Hydra III encounter arc — provisional

A likely first encounter:

> Hydra III begins at 9  
> → existing Auto Slash resumes  
> → CUT 1 → GROW +2 remains active  
> → head count rises rapidly  
> → visible Hydra saturates near 99 heads  
> → logical count crosses 100  
> → Tree View becomes available  
> → logical population continues toward 729  
> → NP becomes ready  
> → player releases NP  
> → regrowth stops  
> → Auto Slash stops as usual  
> → player manually attacks in stopped time  
> → Command Spell III becomes gameplay-eligible  
> → if affordable, third Command Spell slot lights  
> → later purchase begins allowing Auto Slash into NP

The player should feel that Hydra III did not introduce a random new rule.

Instead it exposed that the **existing solution no longer scales comfortably**.

---

## 13. Why this helps tune Command Spell II later

Command Spell II's exact NP-duration / NP-requirement curve should be revisited **after** Hydra III play targets exist.

Hydra III gives a meaningful throughput reference:

> **729 logical heads**

Therefore we can later evaluate Command Spell II duration milestones not only by how they feel in Hydra II, but by how they combine with Command Spell I + III:

> 3 s / 9 s / 27 s / 81 s  
> ×  
> 243 / 81 / 27 / 9 APS

This may let different builds reach comparable Hydra III capability without forcing everyone to complete Command Spell II before leaving Hydra II.

That is the preferred long-form economy structure.

## 14. Highest-value next questions

1. Should Hydra III definitely keep `CUT 1 → GROW +2`, or should Tree structure begin modifying growth before Hydra IV?
2. Is first logical head **100** the right moment to reveal Tree View, or should the player first spend a short period staring at `HEADS > 99` with no explanation?
3. Should Command Spell III first eligibility trigger on **first Hydra III NP release** as proposed, or immediately on Hydra III generation entry?
4. Does the simple **1/9 → 1/3 → 1 Auto-in-NP** ladder feel strong enough, or should the first acquisition grant full Auto immediately and later levels do something else?
5. Should Command Spell III keep the current joke-text **「這裡怎麼沒有 SKIP???」**, or should the third quote come from a different reference family?
